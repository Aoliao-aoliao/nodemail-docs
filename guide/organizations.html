企业邮局 ​

组织与角色 ​

企业邮局把域名、成员、邮箱、套餐和品牌集中到一个组织中。

角色主要权限
所有者管理组织、订阅、成员和关键设置，可转移所有权
管理员管理成员、域名和企业邮箱，权限受组织策略限制
成员使用获分配的企业邮箱和组织资源

邀请成员时填写的 NodeLoc 用户名只会匹配对方已经绑定并验证的 NodeLoc OAuth 身份，不会匹配可自行注册的本地同名账号。普通账号后来绑定 NodeLoc 后也可以被这种方式准确识别。移除成员前应先处理其邮箱、共享关系和仍在进行的业务。所有权转移是关键操作，接收人应先加入组织并确认账号可用。

添加自有域名 ​

  1. 在组织域名页添加域名。
  2. 按页面给出的值配置域名所有权验证记录。
  3. 配置 MX、SPF、DKIM 和 DMARC。
  4. 等待 DNS 生效后重新检查。
  5. 验证完成后创建企业邮箱。

页面显示的记录值以当前组织配置为准，不要照抄其他域名的 DKIM 公钥或验证值。

企业邮箱 ​

组织管理员可以创建、停用和管理企业邮箱。可创建数量和存储空间受当前企业套餐限制。停用邮箱前，应先导出或转交仍需保留的邮件。

组织所有者和管理员具有组织运维权限，可以在权限范围内查看企业邮箱的邮件与附件以处理合规、交接和故障。企业成员不应把组织邮箱当作只有本人可见的私人空间；管理员仍应遵守最小访问和审计原则。

品牌设置 ​

组织可以配置显示名称、Logo 和主色。只有平台已启用企业自定义品牌、组织本身处于生效或宽限状态、企业套餐也处于生效或宽限期，并且访问域名已经验证时，登录页、侧栏、页面标题和主题色才会使用组织设置；平台主域仍显示平台品牌。组织被暂停、套餐过期或不存在有效套餐后，公开页面会立即恢复平台品牌，不会继续展示旧组织品牌。上传 Logo 后若没有立即变化，请刷新缓存并确认文件格式和大小符合页面要求。

刚添加但仍为“待验证”的域名不会出现在品牌适用域名中，也不能按 Host 启用组织品牌。必须同时通过所有权 TXT 和 MX 检查并显示为已验证，品牌才会在该域名及其子域访问时生效。

Logo 只接受经过实际内容检查的 PNG、JPEG、WebP 或 GIF。SVG 不允许上传，修改文件扩展名也不能绕过检查。后台关闭企业自定义品牌，或者组织/套餐不再满足条件时，这些设置会继续保存但暂不展示，公开 Logo 地址也会返回不存在，避免旧品牌文件继续泄露。

发信通道 ​

组织可以在管理页选择 Resend 或 SendFlare，并保存该组织自己的 API Key。系统会把预设转换为认证 SMTP 中继；正常路由只让发往 Microsoft 托管域名的邮件优先使用组织通道，其他外部收件域仍走直接 MX。删除配置后会回到平台的通道选择和直接投递规则。

组织通道当前不接受任意自定义 SMTP 主机。API Key 属于敏感凭据，只能在组织管理页保存，不应写入文档或提交到 Git。

组织中继与平台“系统 SMTP”用途不同：组织中继发送企业业务邮件，系统 SMTP 发送注册验证码、密码重置和找回邮箱验证。

套餐生命周期 ​

组织订阅决定域名数、邮箱数、存储和组织每日发信配额；当前套餐没有独立的成员人数上限字段。组织所有者或管理员可在组织页查看和购买企业套餐，当前用户端没有企业订阅的取消或恢复按钮；需要变更时联系平台管理员。具体价格、周期和权益以套餐页实时显示为准。

企业邮箱发送时，To、Cc、Bcc 的收件人数都会计入当日组织用量；同一组织所有成员与企业邮箱共享这一计数。系统在外部投递前原子预留，按本地投递成功或远端 SMTP 服务器已接受的收件人数结算，并释放未成功部分，避免并发超额。正在投递的保守预留也会暂时显示在今日用量中。组织页显示今日用量与套餐上限；计数按 UTC 日期重置。企业上限为 0 表示不限，且企业发送不占受派成员的个人每日额度或能量。没有生效或宽限期企业套餐时，企业邮箱不能发信。
