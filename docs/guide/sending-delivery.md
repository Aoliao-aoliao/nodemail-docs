# 发信与投递

## 发信资格

能否发信由邮箱状态、所属域名、系统配额、套餐、能量余额和平台策略共同决定。部分域名需要管理员先批准域名发信，再批准用户或邮箱的临时发信申请。

在发信设置中可以查看当前资格、剩余额度和申请状态。审核未通过时，请按页面提示补充用途，避免重复提交相同申请。

## 投递通道

平台可按域名选择直接 MX 投递或外部中继。管理员负责配置 DKIM、HELO、退信处理和中继凭据；普通用户无需填写这些系统参数。注册验证码使用独立系统 SMTP，不经过这里的业务通道。

认证中继要求有效的 SSL/TLS 或 STARTTLS 连接并校验证书。直接投递到外部 MX 使用机会式 STARTTLS：对方支持时加密，对方不支持或握手失败时可能为保证邮件互通而使用明文 SMTP，因此普通邮件不具备端到端加密保证。

发送前会进行地址格式、域名和策略检查。被黑名单或抑制名单命中的收件人会被阻止，以避免持续向无效地址投递。

每日额度按收件人数计算，To、Cc、Bcc 都计入。个人邮箱按用户的个人额度计算，超出免费额度时才可能按后台策略消耗能量；企业邮箱则由同一组织的所有成员共享企业套餐每日额度，不占用成员个人额度或能量。企业每日额度为 `0` 时表示不限，但仍要求组织套餐处于生效或宽限状态。

并发发送会在外部投递前原子预留相应的个人或组织额度、必要能量、通道额度和存储，最终按本地投递成功或远端 SMTP 服务器已接受的收件人数结算，并释放未成功部分。网页写信、SMTP Submission、邮箱/规则转发和自动回复使用同一套个人或组织每日额度口径。每日计数以 UTC 日期为边界，页面会分别展示个人今日用量和组织今日用量。

## 投递结果

当前网页发信会同步尝试本地投递、外部中继或直接 MX，没有独立的长期出站队列。成功表示收件服务器已经接受邮件，不代表一定进入对方收件箱。部分收件人成功时，接口会返回成功与失败数量；全部失败时，原内容会尽量保留为草稿供用户修正后重试。

SMTP Submission 遇到真正的临时网络错误会返回 `451`，由提交邮件的客户端决定何时重试。地址或策略等永久失败会写入失败记录，并避免让客户端无限重试。被抑制的收件人会在连接外部服务器前被拒绝。浏览器或客户端超时后，先检查已发送邮件和管理员邮件流转记录，再决定是否重发。

## 提高送达率

- 使用真实、稳定的发件身份和清晰主题。
- 只给同意接收邮件的地址发信，并及时处理退订和无效地址。
- 避免短时间内突然增加发信量。
- 不发送可执行附件、欺骗性链接或重复垃圾内容。

## DKIM、SPF 与 DMARC

自有域名应同时设置 DKIM、SPF 和 DMARC。DNS 检查通过只代表记录可读取；修改 DNS 后仍需等待全球缓存刷新。管理员可在域名页面重新检查并查看具体缺失项。
