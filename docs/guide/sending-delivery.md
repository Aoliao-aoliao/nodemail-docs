# 发信与投递

## 发信资格

能否发信由邮箱状态、所属域名、套餐配额和平台策略共同决定。部分域名需要管理员先批准域名发信，再批准用户或邮箱的发信申请。

在发信设置中可以查看当前资格、剩余额度和申请状态。审核未通过时，请按页面提示补充用途，避免重复提交相同申请。

## 投递通道

平台可按域名选择直接 MX 投递或外部中继。管理员负责配置 DKIM、HELO、退信处理和中继凭据；普通用户无需填写这些系统参数。

发送前会进行地址格式、域名和策略检查。被黑名单或抑制名单命中的收件人会被阻止，以避免持续向无效地址投递。

## 投递状态

已发送不等于已送达。常见结果包括：

| 状态 | 含义 | 建议 |
| --- | --- | --- |
| 排队 | 正等待投递 | 稍后刷新，不要重复发送 |
| 已投递 | 对方服务器已接受 | 最终是否进收件箱由对方判断 |
| 临时失败 | 网络或对方服务暂时不可用 | 等待系统重试 |
| 永久失败 | 地址、策略或域名被拒绝 | 查看原因后修正地址或联系管理员 |
| 被抑制 | 收件人被安全策略拦截 | 管理员确认原因后处理 |

## 提高送达率

- 使用真实、稳定的发件身份和清晰主题。
- 只给同意接收邮件的地址发信，并及时处理退订和无效地址。
- 避免短时间内突然增加发信量。
- 不发送可执行附件、欺骗性链接或重复垃圾内容。

## DKIM、SPF 与 DMARC

自有域名应同时设置 DKIM、SPF 和 DMARC。DNS 检查通过只代表记录可读取；修改 DNS 后仍需等待全球缓存刷新。管理员可在域名页面重新检查并查看具体缺失项。
