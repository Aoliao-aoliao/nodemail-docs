# 开发者 API

## 创建密钥

在开发者页面创建个人 API 密钥，并只授予业务需要的作用域。完整密钥只在创建时显示一次；丢失后应撤销旧密钥并重新创建。

请求地址、鉴权格式和当前接口定义以开发者页面提供的 OpenAPI 说明为准。示例：

```http
Authorization: Bearer <API_KEY>
Accept: application/json
```

不要把真实密钥写进前端代码、公开仓库、日志或工单。服务端应用应通过环境变量或密钥管理服务注入。

## 作用域

作用域用于限制密钥能够读取或修改的资源。优先创建只读密钥；确需写操作时，再单独创建用途明确、有效期受控的密钥。业务停用或人员变更后立即撤销。

## 响应与错误

API 使用 HTTP 状态码表达结果：`2xx` 表示成功，`400` 表示参数问题，`401` 表示凭据无效，`403` 表示权限不足，`404` 表示资源不存在，`429` 表示请求过快，`5xx` 表示服务端异常。

客户端应设置连接和读取超时；对网络错误及部分 `5xx` 使用带随机抖动的指数退避。创建订单、发送邮件等有副作用的请求不要盲目重试，应先查询结果或使用接口提供的幂等机制。

## 密钥轮换

1. 创建新密钥并赋予相同或更小的作用域。
2. 更新应用配置并验证请求成功。
3. 撤销旧密钥。
4. 检查审计记录，确认没有旧密钥流量。
