# 管理员后台

管理员从 <https://to9.us/app/login?redirect=/admin> 登录。管理员账号与普通用户使用同一登录页，认证成功后根据权限进入后台；首次引导不会要求管理员重复绑定找回邮箱或创建个人邮箱。密码不会以明文保存在源码、数据库或文档中。

## 后台页面

| 页面 | 主要用途 |
| --- | --- |
| 概览面板 | 用户、邮箱、今日邮件与发信、失败/垃圾/删除、运行时、Top 发件人、通道、能量和组织概况 |
| 用户管理 | 搜索筛选用户、查看身份与配额、禁用、重置、强制下线、代入与删除 |
| 邮箱管理 | 搜索邮箱、调整状态、协议访问、归档和查看归属 |
| 系统设置 | 注册、SMTP 认证邮件、Turnstile、配额、存储、通知、协议、TLS 和反垃圾 |
| 系统公告 | 新建、编辑、发布和删除公告，按所有用户、个人用户或指定企业投放 |
| 域名管理 | 域名注册策略、Catch-All、发信限制、DKIM、DNS 健康和发信申请 |
| OAuth 配置 | NodeLoc、Google、GitHub 等提供方的端点、客户端凭据、作用域和开关 |
| 工单管理 | 搜索、回复、优先级、状态与内部备注 |
| 审计日志 | 按用户、动作、IP、目标与时间筛选高风险操作 |
| 邮件流转 | 按邮箱、地址、主题、方向、状态和时间排查邮件 |
| 黑名单 | 管理邮箱、域名、IP 或 CIDR 规则、来源、备注与过期时间 |
| 套餐与支付 | 个人/企业套餐、支付通道、订阅补单和组织列表 |
| 兑换码管理 | 生成、限制、停用和查询兑换记录 |
| 订单管理 | 搜索订单、核对支付流水及在充分证据下执行补偿 |

侧边栏条目都对应真实路由。版本刚升级时，旧浏览器标签可能仍引用已经删除的前端分块；系统会在检测到分块加载失败后对目标页面刷新一次。若仍“点击没反应”，先强制刷新页面，再检查浏览器网络请求和反向代理缓存。

## 日常检查

- 检查服务健康、磁盘、近期错误、异常登录和管理员操作。
- 查看待处理的发信申请、域名验证和工单。
- 关注发送失败记录、抑制名单、通道额度和发信量变化。当前没有独立的长期出站重试队列。
- 结合服务端支付日志核对回调验证结果，再核对订单、钱包流水和订阅状态。
- 检查网页及 587、993、995 实际握手证书与 DNS。
- 抽查注册验证码、找回密码、Turnstile 和 OAuth 登录。

## 高风险操作

永久删除用户、彻底清理邮箱、管理员重置密码、重置 2FA、授予管理员、修改域名密钥、代入登录和变更支付配置都会影响真实业务。执行前确认目标对象、影响范围和审计记录。

管理员代入登录只用于复现用户界面问题。代入会话禁止改密码、改 2FA、绑定邮箱或 OAuth、创建应用专用密码和 API Key；需要验证这些功能时使用专用测试账号。

## 审计原则

管理员使用个人独立账号，避免多人共用。敏感操作后检查审计日志；人员离开或权限变化时立即停用账号、强制下线并轮换其接触过的凭据。删除用户不会删除对应的必要审计历史，操作者账号引用会安全置空。
