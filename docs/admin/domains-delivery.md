# 域名与邮件投递

## 域名上线流程

1. 添加域名并设置用途与归属。
2. 生成并发布所有权验证记录。
3. 发布 MX、SPF、DKIM 和 DMARC。
4. 在后台执行 DNS 健康检查。
5. 配置收信、发信策略和配额。
6. 用测试邮箱完成收信、发信与回复验证。

DNS 页面给出的主机名和记录值是唯一准确信息。轮换 DKIM 时先发布新公钥，确认生效后切换签名，再移除旧记录。

## 发信审批

平台可分别控制域名发信资格和用户发信资格。审核时核对用途、预计量级、收件人来源及退订机制。异常批量发送时应先暂停资格，再调查账号和密钥是否泄露。

## 投递与抑制

直接 MX 投递依赖服务器身份、DNS、IP 信誉和远端策略；中继投递还依赖供应商凭据和额度。永久失败或多次网络失败的收件人可进入抑制名单，防止持续重试。

解除抑制前先确认地址已恢复有效。仅清空名单而不处理根因，会再次产生退信并影响信誉。

## rspamd 隔离区

隔离区用于查看被反垃圾策略拦截的邮件。管理员可以释放、删除或协助申诉。释放前检查发件域、认证结果、链接和附件；可疑内容不应投递给用户。

## TLS

`mail.to9.us` 的 IMAPS、POP3S 和 SMTP STARTTLS 应提供有效且主机名匹配的证书。证书更新后，要确认实际邮件服务已经加载新文件，而不只是网页代理更新成功。
