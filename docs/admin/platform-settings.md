# 平台设置与安全

## 基础设置

基础设置包括站点名称、公开地址、应用路径、默认时区、注册开关和邮件相关限制。公开地址必须与实际 HTTPS 域名一致，否则 OAuth 回调、通知链接和跨域策略可能失败。

当前应用位于 `/app/`。调整路径时需要同时更新前端构建、反向代理、OAuth 回调和旧地址跳转。

## 登录与 OAuth

管理员可配置注册、邮箱验证码、密码找回、绑定邮箱和 OAuth 提供方。每个 OAuth 提供方都应使用精确回调地址，并只保存最少权限的客户端密钥。

登录限流、访问令牌与刷新令牌参数属于安全设置。缩短有效期会增加登录频率，延长有效期则提高凭据泄露后的风险；修改后应同步考虑强制退出策略。

## 注册保护与 Turnstile

正式系统当前允许所有访客提交注册，但启用邮箱验证后，注册者必须填写找回邮箱并完成验证码验证，不能再用空邮箱直接建立账号。注册接口还按来源 IP 限速，默认每小时 5 次、每天 20 次；后台可通过 `registration_ip_hourly_limit` 和 `registration_ip_daily_limit` 调整。

Cloudflare Turnstile 需要在 Cloudflare 控制台为 `to9.us` 创建站点，然后把 **Site Key** 和 **Secret Key** 同时填入后台再开启。Site Key 会公开给浏览器，Secret Key 只保存在服务端。系统不允许在缺少任一密钥时从后台开启；若通过环境变量误开但密钥不完整，登录和注册接口会返回 503，避免表面开启、实际绕过。

Turnstile 可以明显减少自动注册、撞库和脚本请求，但不能单独保证没有机器人滥用。应同时保留邮箱验证码、登录与注册限速、每日发信配额、异常日志和封禁措施。Cloudflare 故障或服务端无法取得验证结果时，受保护接口会暂时拒绝请求。

## 邮件与通知

系统通知邮件需要可用的发件身份和投递通道。站内公告可按受众发布；Telegram 通知需要机器人凭据和公开回调条件。保存后分别执行测试，不要把生产凭据粘贴到日志或文档。

## 支付

支付提供方通常需要商户号、签名密钥、回调地址和启用开关。必须校验服务端回调签名，并通过订单状态防止重复入账。停用提供方前先处理仍在等待回调的订单。

## 密钥管理

JWT、数据库密码、OAuth 密钥、支付密钥、Telegram Token、SMTP 中继密码和 TLS 私钥不得提交到 Git。使用环境变量、受限配置文件或密钥管理系统保存，并限制文件权限。

Docker Compose 不再提供 PostgreSQL 默认密码，`POSTGRES_PASSWORD`、`JWT_SECRET` 和正式公开地址必须由部署环境明确提供。基础镜像使用固定摘要，升级镜像时应先审计并在隔离环境重建。

## 配置变更

关键配置变更前记录旧值和变更原因；保存后检查健康状态、日志及对应业务。密钥一旦暴露，应立即轮换，删除聊天或 Git 历史不能替代轮换。
