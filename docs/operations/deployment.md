# Docker 部署

本文面向自行部署草丛 Mail 的运维人员。生产源码仓库保持私有；本公开仓库只保存文档，不提供完整应用源码。

## 服务组成

标准部署由以下容器组成：

| 服务 | 用途 |
| --- | --- |
| `db` | PostgreSQL 业务数据 |
| `redis` | 缓存、会话或队列辅助 |
| `rspamd` | 反垃圾与隔离处理 |
| `backend` | Web API、SMTP、IMAP 和 POP3 服务 |
| `frontend` | `/app/` 邮箱应用静态站点 |
| `website` | 产品官网静态站点 |
| `nginx` | 同域路由与静态资源入口 |

公网 HTTPS 可由宿主机面板或独立反向代理终止，再转发到 Docker Web 入口。邮件端口直接映射时应配置主机防火墙。

## 前置条件

- 支持 Docker Compose 的 Linux 主机。
- 可控域名和 DNS，能够设置 A、MX、TXT 记录。
- 开放 Web、SMTP Submission、IMAPS 和 POP3S 所需端口。
- 为 PostgreSQL 数据卷准备持久化磁盘和备份空间。

## 配置原则

以私有源码仓库提供的示例环境文件为起点，生成全新的数据库密码、JWT 密钥和各外部服务密钥。不要直接使用示例值，也不要提交真实 `.env`。

公开 URL、邮件主机名和应用路径要保持一致。草丛 Mail 当前网站使用根路径，邮箱应用使用 `/app/`；反向代理应保留旧入口重定向。

## 首次启动

```bash
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail=200 backend nginx
```

后端启动时会按顺序执行数据库迁移。迁移失败时不要反复重启或手工标记成功，应先根据日志修复具体问题。

## DNS

至少配置：

- Web 与邮件主机的 A/AAAA 记录。
- 指向邮件主机的 MX 记录。
- 授权实际发信源的 SPF。
- 与后台当前选择器、公钥一致的 DKIM。
- 从观察策略开始并逐步收紧的 DMARC。

反向 DNS 通常由服务器提供商配置，应与邮件主机名匹配。

## TLS

网页与邮件协议都必须使用有效证书。邮件服务需要能够读取证书链和私钥；文件更新后重启或重载后端，并分别验证 587 STARTTLS、993 和 995 实际提供的新证书。

自动续期脚本应只允许 root 读取，并在续期后同步应用配置和重载服务。不要把私钥复制到仓库或容器镜像。
